# OpenTofu adoption

This root imports existing non-fork repositories and initially enforces only
`squash_merge_commit_title = PR_TITLE` and `delete_branch_on_merge = true`.
Unrelated settings are preserved. Archived repositories are imported read-only.
Provider 6.13.0 is pinned; OpenTofu 1.8+ is required.

## Bootstrap

Use a credential with organization-wide metadata access and repository
Administration write permission. Authentication comes from `GITHUB_TOKEN`.
Credentials MUST NOT be committed or written into configuration. File sync
SHOULD use a separate app credential with narrower contents/PR/workflow access.

From the repository root:

```bash
gh auth status
python3 .github/scripts/discover.py
tofu -chdir=tofu init
tofu -chdir=tofu providers lock -platform=linux_amd64 -platform=darwin_arm64
tofu -chdir=tofu fmt -check -recursive
tofu -chdir=tofu validate
```

Review and commit generated `tofu/.terraform.lock.hcl` before first apply. It MUST
be generated by OpenTofu, never hand-edited. Subsequent initialization MUST use
`-lockfile=readonly`. This scaffold deliberately contains no fabricated lockfile:
OpenTofu/provider installation was unavailable in the preparation environment.

## State and review

No organization backend has been selected. The default local backend supports
a single-operator pilot. Its `tofu/terraform.tfstate` MUST be retained securely
and backed up; it MUST NOT be discarded after adoption or replaced with unrelated
state. Local runtime data is ignored by Git.

Before shared or CI-driven apply, operators MUST configure a durable backend with
encryption, locking, restricted access, and backups. Backend credentials MUST
stay outside committed configuration. Migrate pilot state with
`tofu init -migrate-state` when selecting that backend. Actions artifacts and
caches MUST NOT serve as authoritative state.

Imports are configuration-driven and idempotent. An imported address makes its
import block inert. Discovery is idempotent and does not mutate GitHub. Its
generated inventory contains private repository names and MUST remain local.
Review it against the complete organization inventory before planning.

```bash
tofu -chdir=tofu init -lockfile=readonly
tofu -chdir=tofu plan -input=false -out=adoption.tfplan
tofu -chdir=tofu show adoption.tfplan
```

The plan MUST import existing objects without creating or deleting repositories.
Only the two owned settings MAY change. Visibility, default branches, merge
methods, `allow_auto_merge`, features, rulesets, and permissions MUST remain
unchanged. A stable repository-ID mismatch MUST stop adoption. Investigate any
other proposed change before apply.

After reviewing that exact saved plan:

```bash
tofu -chdir=tofu apply adoption.tfplan
tofu -chdir=tofu plan -input=false -detailed-exitcode
```

The fresh plan MUST exit 0. Status 2 means changes remain; status 1 means failure.
Serialize all writers. Adopting additional fields requires replacing their
`ignore_changes` entries with explicit desired values in a reviewed change.

## Repository lifecycle changes

`prevent_destroy` protects resources while their lifecycle configuration remains
present. Removing a resource block also removes that protection. It does not
replace plan review or the organization lifecycle guardrails.

Active and archived repositories use distinct addresses. If a repository is
archived, move its state address before planning with refreshed inventory:

```bash
tofu -chdir=tofu state mv 'github_repository.active["example"]' 'github_repository.archived["example"]'
```

The reverse move handles unarchiving. For a rename, move the old indexed address
to the new name and refresh inventory. Review the plan; the stable ID MUST match.
Removed repositories and intentional ownership removal require explicit state
review. Operators MUST NOT automate `state rm` to make a destructive plan pass.

Repository creation, teams, permissions, and fully representable rulesets belong
here when explicitly adopted. The initial discovery/import path never creates
replacement repositories after a failed import.
